4. 8 维 Schema → SemanticAnchor 映射

8 维是场景全栈契约；SemanticAnchor 只取其中「引用级」切片，或从 derived 源派生。

8 维文件与 SemanticAnchor说明
schema.json 强相关 fields → ConstraintUnit（kind=field/param/enum）；最强血缘
api.json 部分 endpoints → kind=endpoint/signature；不要完整 api 维
model.json derived 源 DTO/符号名可派生 symbol；不复制 model 维文件
table.json / query.json derived 源 列名/字段映射 → declared/derived 约束来源
ui.json 不包含 布局/组件 — 非引用级语义约束
rule.json 不包含 业务规则 — 规则引擎（达层）
event.json 不包含 MQ 契约 — 不在开源协议范围

6. OpenSpec 仍补不上的缝（语义锚存在理由）

Apply 中的问题OpenSpecSemanticAnchor
spec 写 ticker，代码写 sym❌ tasks 不逐字段验✅ drift
枚举 buy/sell，代码写 long❌✅ enum violation
Planner → Coder handoff 丢约束❌ 靠长 context✅ bind bundle
幻觉 API / 错签名❌ 除非 E2E 失败✅ signature 锚定
敏感字段明文 log❌ ui-spec 不管运行时✅ policy + verify
一句话：OpenSpec 让 spec 持久且可审；SemanticAnchor 让 Agent 在写代码时守 spec 的「引用面」。 见 限价报单 Walkthrough（7→0）。
